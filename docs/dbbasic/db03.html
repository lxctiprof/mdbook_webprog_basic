문서 검색에서 연간%계획 이라고 입력

전체 일치가 아닌 부분 일치되는 자료를 찾기 위해 사용

  • 예: 이름이 ’도근’으로 시작하는 도근점만 찾기
select * from dogun where name like '도근%';

like 연산자를 쓸 때의 % 기호

  • 모든 문자라는 뜻.

  • like ‘나%’ : ’나’로 시작되는 모든 자료, 예: ‘나지적’, ‘나영성’ 등

  • like ‘%나’ : ’나’로 끝나는 모든 자료, 예: ‘오빛나’, ‘아맛나’ 등

  • like ‘%나%’ : 자료 중 ’나’가 들어간 모든 자료, 예: ‘일어나’, ‘가나다’ 등

공사 ERP에서 문서 검색할 때 벌어지는 일

연간 측량 계획, 연간 휴가 계획, 연간 인사 관리 계획 등 연간 ~ 계획을 검색하고 싶다면?

문서 검색할 때 연간%계획 이라고 입력

select * from 공문 where title like '연간%계획';

입력된 자료 수정 시 where 절

이름이 ’도근점 1’인 자료를 찾아 메모를 ’중앙선 바로 위’로 바꾼다.

* update 문을 쓸 때는 where 절을 먼저 써 놓는 버릇을 들여 전체 데이터의 값을 바꾸는 실수를 하지 않도록 하자.

dogun 테이블의 문제점

1. update가 필요한 경우, where 절에 이름으로 검색할 수 밖에 없는데, 같은 이름을 가진 자료가 모두 변경됨

update dogun set memo = '지워져서 잘 안보임' where name='도근점 4';
  • 해결방법: key 추가

2. delete 하는 경우, where 절에 이름으로 검색할 수 밖에 없는데, 같은 이름을 가진 정보가 모두 삭제됨.

delete from dogun where name = '도근점 4';
  • 해결방법: key 추가

3. 이름을 넣지 않아도 자료를 입력할 수 있어 무슨 자료인지 알 수가 없는 경우가 있음

  • 해결방법: not null constraints

4. 이름, X, Y, 좌표체계는 꼭 필요한 정보인데 넣지 않아도 insert가 됨.

  • 해결방법: not null constraints

빈 칸 문제

not null 등 제약 조건을 지키지 않으면 에러가 발생함
= DB 저장이 안됨
= DB에 있는 모든 자료에는 id, x, y, coord, name 정보가 반드시 있음.

동명이인 문제

새로운 dogun 테이블의 문제점

같은 이름 문제, 빈 칸 문제는 해결되었지만 동일 ID 입력 가능 문제가 남음

insert into dogun (id, x, y, coord, name) values (15, 9.5, 8.7, 100, '도근점 15');
insert into dogun (id, x, y, coord, name) values (15, 8.5, 1.4, 100, '도근점 16');

위 코드는 문제없이 입력된다.

id를 똑같이 15로 줬는데도 문제없이 입력되었다.

*동일 ID가 있으면 같은 이름 도근점과 같은 문제 발생

update dogun set memo='유실된 듯함.' where id=15;

새로운 dogun 테이블의 문제 해결

primary key constraints(제약조건)

  • 반드시 값이 있어야 함(NOT NULL)

  • 유일한 값이어야 함(UNIQUE)

  • 이런 성질 때문에 primary key 컬럼은 그 자료를 대표한다.

기본키(primary key)를 적용 테이블 다시 만들기

drop table dogun;

create table dogun
(
    id int primary key,
    x float8 not null,
    y float8 not null,
    coord int not null,
    name varchar(20) not null,
    memo varchar(100)
);

새 dogun 테이블로 문제 해결

insert into dogun (id, x, y, coord, name) values (15, 9.5, 8.7, 15, '도근점 15');
insert into dogun (id, x, y, coord, name) values (15, 8.5, 1.4, 15, '도근점 15-2');

두 번째 줄은 실행 중 에러 발생

id는 primary key로 설정되어 있는 상태.

앞에서 id가 15인 값 자료를 저장했는데, 또 ID가 15인 자료를 저장할 수 없기 때문.

이제 같은 id를 가지는 데이터는 존재하지 않게 되었다.

정리: 좋은 테이블

  • id를 가진다.

  • id가 기본키(primary key)이다.

  • 값이 비면 안되는 필드는 not null로 설정한다.

postgreSQL의 주요 constraints

  • NOT NULL

  • UNIQUE

  • PRIMARY KEY

  • FOREIGN KEY

  • CHECK

primary key 용 ID 숫자값 자동 증가

insert into dogun (id, x, y, coord, name) values (15, 9.5, 8.7, 15, '도근점 15');
insert into dogun (id, x, y, coord, name) values (15, 8.5, 1.4, 15, '도근점 15-2');

ID값은 사람이 굳이 알지 않아도 되는 값.

그런데도 귀찮게 매 번 ID로 다른 값을 줘야 함.
그래서 대부분 1부터 하나씩 증가하는 값을 넣어주는 방법을 선택함.

대부분의 DBMS에서 PK로 잡은 숫자형 ID를 위해 자동 증가하는 방법을 제공하고 있다.

postgreSQL에서 제공하는 자동 증가 방법

  • sequence
  • serial
  • generated as identity

postgreSQL의 PK 자동 증가 - serial

  • 테이블 생성할 때부터 자동 증가되도록 설정.

  • 단, 표준 SQL이 아닌, postgreSQL에서 지원하는 기능이라 다른 DBMS로 이전 시 문제가 됨.

create table auto2
(
	id SERIAL primary key,
	name varchar(10)
);

이 테이블에 대한 insert 문

insert into auto2 (name) values ('너지적');

* id는 기본키라 반드시 입력해야 하지만, 자동 증가되니 insert 문에 포함하지 않는다.

자동 증가 기능 추가한 dogun 테이블 생성

drop table dogun;

create table dogun
(
    id serial primary key,
    x float8 not null,
    y float8 not null,
    coord int not null,
    name varchar(20) not null,
    memo varchar(100)
);
