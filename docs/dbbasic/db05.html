중구난방 데이터 문제 해결 2 - postgreSQL

  • 측량사 목록을 담은 surveyors 테이블 생성

  • surveyor 테이블에 저장된 이름만 사용해서 해결

Relation(관계)

  • 객체(object)들 사이의 관계

  • 주로 테이블 간의 관계

<출처: 위키백과>

RDBMS가 Relation을 위해 해 주는 일

Foreign KEY(FK)

“지금부터 dogun 테이블의 surveyor 필드에는
surveyors 테이블의 name 필드에 있는 값만 쓸 수 있다!”

“다른 값은 절대로 못 들어와!”

라고 선언할 수 있다.

이게 FOREIGN KEY.

Foreign KEY 이해하기

FOREIGN KEY(FK) 거는 방법

drop table dogun;

create table dogun
(
    id serial primary key,
    x float8 not null,
    y float8 not null,
    coord int not null,
    name varchar(20) not null,
    memo varchar(100), 
    surveyor varchar(10),

    constraint FK_DOGUN_SURVEYOR
    foreign key (surveyor)
    references surveyors(name)
);

dogun 테이블 생성 에러 원인과 해결

그런데 위 코드는 에러가 난다.

ERROR:  there is no unique constraint matching given keys for referenced table "surveyors“
오류:  참조되는 "surveyors" 테이블을 위한 주워진 키와 일치하는 고유 제약 조건이 없습니다

이유: 참조 건 테이블의 name 필드에 UNIQUE constraint가 안 걸려 있다)
해결: surveyor 테이블의 name 필드에 UNIQUE constraint를 걸어준다.

unique한(같은 값이 없는) 값을 줘야만 데이터로서의 가치가 있다.

surveyor 테이블 새로 생성

drop table surveyors;

create table surveyors
(
    name varchar(10) UNIQUE
);

샘플 데이터 다시 입력

insert into surveyors (name) values ('홍길동');
insert into surveyors (name) values ('박길동');
insert into surveyors (name) values ('고길동');

surveyors에 UNIQUE 를 걸어준 다음 dogun 테이블을 다시 생성하자.

create table dogun
(
    id serial primary key,
    x float8 not null,
    y float8 not null,
    coord int not null,
    name varchar(20) not null,
    memo varchar(100), 
    surveyor varchar(10),

    constraint FK_DOGUN_SURVEYOR
    foreign key (surveyor)
    references surveyors(name)
);

다른 값은 입력 안 되는 것 확인

먼저 입력 잘 되는 것 확인

values
(10, 10, 101, '도근 100', '고길동');

확인

확인할 점

  1. id가 1로 자동 증가의 시작이 잘 입력됨

  2. 고길동이 제대로 입력됨.

다음 입력되면 안 되는 것 시도하는 경우

입력 시도

values
(10, 10, 101, '도근 100', '고 길동');

오류:  "dogun" 테이블에서 자료 추가, 갱신 작업이 "fk_dogun_surveyor" 참조키(foreign key) 제약 조건을 위배했습니다
상세정보:  (surveyor)=(고 길동) 키가 "surveyors" 테이블에 없습니다.

업데이트 시도

상세정보:  (surveyor)=(고 길동) 키가 "surveyors" 테이블에 없습니다.

도근점과 측량사 관계의 문제점

동명이인 측량사 문제

  • 한 지사에 정말로 박길동이 2명 있다면?

수정 문제

  • 오타가 발견되었다. 이제보니 ’구길동’을 ’고길동’으로 잘못 적었다.
  • 만약 구길동이 100개의 도근을 설치했다면 100개의 데이터를 update 해야 한다.
  • DBMS에도 무리를 주고, DB 자체의 안정성에도 위협이 될 수 있다.

측량사 테이블 문제 해결

  • surveyors 테이블에 int type의 ID (primary key) 추가

측량사 테이블 삭제하고 다시 생성

drop table surveyors;

create table surveyors
(
    id int primary key,
    name varchar(10)
);

실행 결과

오류:  "surveyors" 이름의 릴레이션(relation)이 이미 있습니다

이유: 이 오류는 생성단계(create table)이 아닌 맨 윗 줄 drop table 단계에서 발생한 오류임. 이 테이블의 정보를 dogun 테이블에서 사용하고 있는데 삭제하면 dogun 테이블은 붕 뜨게 된다. 그래서 테이블 삭제를 아예 안 시켜주는 거.

drop table dogun;
drop table surveyors;

create table surveyors
(
    id int primary key,
    name varchar(10)
);

* 여기서는 id int 를 했지만, 자동 증가를 하고 싶다면 id serial 도 시도해 보자.

그래서 dogun 테이블 먼저 삭제하고,
그 다음 surveyors 테이블을 삭제하고,
surveyors 테이블을 다시 생성한다.

그리고 dogun 테이블을 생성한다.

dogun 테이블을 만들려면, dogun에서 참조하는 테이블인 surveyors 테이블이 만들어져 있는 상태여야 한다.

동명 이인 문제 해결

insert into surveyors (id, name) values (1, '홍길동');
insert into surveyors (id, name) values (2, '박길동');
insert into surveyors (id, name) values (3, '구길동');
insert into surveyors (id, name) values (4, '박길동');

동명이인 박길동이 2명 입력되어도 id 2, 4로 명백히 구분되기 때문에 동명 이인도 아무 문제없이 입력할 수 있다.

이런 동명이인 구분을 명확히 하기 위해 사번 혹은 주민등록번호를 기본키로 사용하는 거.

Join - 테이블 간의 결합

  • dogun과 surveyors 테이블을 결합해 측량사 부분에 숫자가 아닌 ‘홍길동’, ‘구길동’ 과 같은 실제 측량사 이름이 보이도록 하는 기법

  • 우리가 홈페이지, ERP 등에서 보는 DB 자료는 거의 100% join 한 결과물이다.

join 이해하기

join을 위한 select 문(방법 1)

select 
    dogun.id, dogun.name, 
    surveyors.name 
from 
    dogun, surveyors 
where 
    dogun.surveyor = surveyors.id;

join을 위한 select 문(방법 2 - 추천)

select 
    dogun.id, dogun.name, 
    surveyors.name 
from 
    dogun join surveyors 
on
    dogun.surveyor = surveyors.id;

or

where 절에서 사용.

A이거나 B이거나.

A의 조건을 만족하거나 B의 조건을 만족하거나, 2개의 조건 중 하나 이상을 만족시키는 자료는 모두 찾아낸다.

Q. 짜장면을 좋아하거나 고기완자를 좋아하는 사람만 출력하되, id, 이름만 출력

select 
    ID, name
from
    address
where 
    food = 1 or food = 4;

Q. 짜장면을 좋아하거나 고기완자를 좋아하는 사람만 출력하되, id, 이름, 음식 이름 출력

select 
    address.ID, address.name, foods.name as food
from
    address join foods
on  
    address.food = foods.ID
where     
    (food = 1 or food = 4);

where 절에서 사용.

in 뒤의 괄호 안에 있는 모든 값을 찾아낸다. 편하지만 대체로 괄호 안에는 500개 이상을 넣을 수 없다.

Q. 짜장면, 짬뽕 등 각 음식별로 좋아하는 사람의 수를 출력

select 
    food, count(food)
from
    address
group by
    food;

group by

group by FOOD 를 하면
DBMS는 같은 food 값을 가지는 자료끼리 모은다.

홍길동, 박길동이 food가 1로 하나의 그룹으로 모이고,
박길동이 food가 2로 하나의 그룹으로 모이고,
최길동, 나길동이 food가 3으로 하나의 그룹으로 모이고,
윤지원, 고길동이 food가 4로 하나의 그룹으로 모인다.

Q. 짜장면, 짬뽕 등을 좋아하는 사람의 수를 출력하되, 음식 이름이 나타나도록

select 
    foods.name, foodCount
from
    (
        select 
            food, count(food) as foodCount
        from
            address
        group by
            food
    ) A
    , foods
where 
    A.food = foods.ID;
