문서 검색에서 연간%계획 이라고 입력

전체 일치가 아닌 부분 일치되는 자료를 찾기 위해 사용

  • 예: 이름이 ’도근’으로 시작하는 도근점만 찾기
select * from dogun where name like '도근%';

like 연산자를 쓸 때의 % 기호

  • 모든 문자라는 뜻.

  • like ‘나%’ : ’나’로 시작되는 모든 자료, 예: ‘나지적’, ‘나영성’ 등

  • like ‘%나’ : ’나’로 끝나는 모든 자료, 예: ‘오빛나’, ‘아맛나’ 등

  • like ‘%나%’ : 자료 중 ’나’가 들어간 모든 자료, 예: ‘일어나’, ‘가나다’ 등

공사 ERP에서 문서 검색할 때 벌어지는 일

연간 측량 계획, 연간 휴가 계획, 연간 인사 관리 계획 등 연간 ~ 계획을 검색하고 싶다면?

예: 나이 순으로 정렬, 나이의 역순으로 정렬

select * from dogun order by name;
select * from dogun order by name desc;	»  이름의 역순으로 정렬

order by 뒤에는 여러 필드를 정해줄 수 있다. 이 때 필드의 순서대로 우선순위를 갖는다.

select * from dogun order by name, x;

먼저 이름의 가나다 순으로 정렬하고, 이름이 같은 도근점들이 있으면 그 도근점끼리는 x 좌표 순으로 정렬한다.

실습

1. dogun 테이블에서 X좌표 순으로 정렬

2. dogun 테이블에서 Y좌표 순으로 정렬

3. dogun 테이블에서 메모의 가나다 순으로 정렬

4. dogun 테이블에서 이름이 ’도근점 4’이 자료들만 X 좌표 순으로 정렬

5. dogun 테이블에서 이름에 ’도근’이 들어가고 x좌표가 10.0보다 큰 모든 자료 검색해 이름 순으로 정렬하고, 이름이 같은 도근점이 있으면 y좌표 순으로 정렬

6. dogun 테이블에서 메모에 ’연석’이 들어가고 y좌표가 10.0보다 작은 모든 자료 검색해 이름 순으로 정렬하고, 이름이 같은 도근점이 있으면 x좌표 순으로 정렬

입력한 자료 수정

  • CRUD 중 U(Update)에 해당

  • 문구

update [테이블명] set [필드명] = [값]
where [조건]

예

* 아래 코드는 강사만 실행한다.

update dogun set name = '도근점';

* dogun 테이블의 모든 자료의 name을 ’도근점’으로 바꾼다

입력된 자료 수정 시 where 절

이름이 ’도근점 1’인 자료를 찾아 메모를 ’중앙선 바로 위’로 바꾼다.

update dogun set memo = '중앙선 바로 위' where name='도근점 1';

* update 문을 쓸 때는 where 절을 먼저 써 놓는 버릇을 들여 전체 데이터의 값을 바꾸는 실수를 하지 않도록 하자.

실습

1. dogun 테이블에서 이름이 ’도근점 2’인 자료의 x 좌표를 바꾸자.

2. dogun 테이블에서 메모에 ’연석’이 들어간 자료의 x, y 좌표를 0, 0으로 바꾸자.

입력한 자료 삭제

  • CRUD 중 D(Delete)에 해당

  • 문구

delete from [테이블명] 
where [조건]

예

* 아래 예제는 실제 해보지는 말자

delete from dogun;

* dogun 테이블의 모든 자료를 삭제한다.

테이블 자체는 남아있음. 자료만 삭제되는 것.

입력한 자료 삭제 시 where 절

예

delete from dogun where name='도근점 1'

* 이름이 ’도근점 1’인 자료를 찾아 모두 지운다.

* delete 문을 쓸 때는 where 절을 먼저 써 놓는 버릇을 들여 전체 데이터를 모두 삭제해 버리는 일이 없도록 하자.

실습

1. dogun 테이블에서 이름이 ’dogun 2’인 자료를 삭제하자.

2. dogun 테이블에서 메모에 ’연석’이 들어간 자료를 모두 삭제하자.

3. dogun 테이블에서 이름이 ’도근’으로 시작하고 x 좌표가 10.0 이상인 모든 자료를 삭제하자.

4. dogun 테이블은 남겨두고 dogun 테이블의 모든 자료를 삭제하자.

dogun 테이블의 문제점

1. update가 필요한 경우, where 절에 이름으로 검색할 수 밖에 없는데, 같은 이름을 가진 자료가 모두 변경됨

update dogun set memo = '지워져서 잘 안보임' where name='도근점 4';
  • 해결방법: key 추가

2. delete 하는 경우, where 절에 이름으로 검색할 수 밖에 없는데, 같은 이름을 가진 정보가 모두 삭제됨.

delete from dogun where name = '도근점 4';
  • 해결방법: key 추가

3. 이름을 넣지 않아도 자료를 입력할 수 있어 무슨 자료인지 알 수가 없는 경우가 있음

  • 해결방법: not null constraints

4. 이름, X, Y, 좌표체계는 꼭 필요한 정보인데 넣지 않아도 insert가 됨.

  • 해결방법: not null constraints

primary key constraints(제약조건)

  • 반드시 값이 있어야 함(NOT NULL)

  • 유일한 값이어야 함(UNIQUE)

  • 이런 성질 때문에 primary key 컬럼은 그 자료를 대표한다.

postgreSQL에서 제공하는 자동 증가 방법

  • sequence
  • serial
  • generated as identity

like 연산자

공사 ERP에서 문서 검색할 때 꿀팁

연간 측량 계획, 연간 휴가 계획, 연간 인사 관리 계획 등 연간 ~ 계획을 검색하고 싶다면?

문서 검색에서 연간%계획 이라고 입력

전체 일치가 아닌 부분 일치되는 자료를 찾기 위해 사용

  • 예: 이름이 ’도근’으로 시작하는 도근점만 찾기
select * from dogun where name like '도근%';

like 연산자를 쓸 때의 % 기호

  • 모든 문자라는 뜻.

  • like ‘나%’ : ’나’로 시작되는 모든 자료, 예: ‘나지적’, ‘나영성’ 등

  • like ‘%나’ : ’나’로 끝나는 모든 자료, 예: ‘오빛나’, ‘아맛나’ 등

  • like ‘%나%’ : 자료 중 ’나’가 들어간 모든 자료, 예: ‘일어나’, ‘가나다’ 등

공사 ERP에서 문서 검색할 때 벌어지는 일

연간 측량 계획, 연간 휴가 계획, 연간 인사 관리 계획 등 연간 ~ 계획을 검색하고 싶다면?

문서 검색할 때 연간%계획 이라고 입력

select * from 공문 where title like '연간%계획';

GIS와 공간데이터 이해

1. 공간정보와 지리정보시스템

  • 공간정보(Geospatial Information)

    • 지상, 지하, 수상, 수중 등 공간 상에 존재하는 자연 또는 인공적인 객체에 대한 위치정보 및 이와 관련된 공간적 인지와 의사결정에 필요한 정보(공간정보산업 진흥법)

  • 지리정보시스템(Geographic Information System, GIS)

    • 공간적 문제를 해결하기 위해 다양한 공간자료를 수집, 구축, 유지, 관리, 편집하고 분석과 모델링을 통해 추출된 고부가가치의 정보를 표현하고 출력할 수 있게 고안된 종합적인 정보처리시스템

  • 지리정보시스템 자료

    • 실세계에 나타나는 형상들에 대한 정확한 위치를 컴퓨터를 통해서 나타내고, 그 형상에 대한 여러 가지 속성을 컴퓨터를 통해 표현하는 것

2. 실세계 모델링 방법

  • 객체 기반 모델(Objected-based Model)

    • 도시, 건물, 고속도로와 같이 불연속적(이산적)이고 명확한 객체들로 구성된 지리적 공간을 다룸

    • 확인할 수 있는 경계나 공간적인 범위를 가져야 함

    • 속성으로써 참조되는 하나 이상의 특성으로 묘사될 수 있어야 함

    • 객체의 특성과 기록된 축척에 따라 공간객체는 점, 선, 면이라는 공간적 요소로 표현

    • 대부분 연속적인 좌표형태로 데이터가 표현되기 때문에 벡터데이터 모델(vector data model) 이라고 함

  • 필드 기반 모델(Field-based Model)

    • 불명확하고 특정한 범위가 없는 공간에서 연속적으로 변화하는 실세계 형상

    • 규칙적인 격자 형태나 불규칙적인 점 데이터로 표면을 표현

    • 공간단위는 공간적 현상을 묘사한 격자 형태이므로 래스터 모델(raster model)이라 함


3. 벡터와 래스터 모델

  • 벡터 vs 래스터 데이터


  • 벡터 데이터의 종류

    • 점(Point)

      • 공간상 대상물에 대한 지점 또는 장소 표현(예: 교통사고지점, 패스트푸드점 위치 등)

      • 하나의 위치 좌표(x, y)로 속성 정보가 구성됨

    • 선(Line / Polyline)

      • 실질적 또는 무형의 대상을 표현(예: 도로, 강, 행정구역 경계 등)

      • 위치와 길이라는 속성을 갖는 1차원 사상으로 최소 2개의 점을 갖고 있음

      • 일반적으로 각각의 점을 노드(node), 두 개의 노드를 잇는 선분을 엣지(edge)라 부름

    • 면(Polygon)

      • 대상물의 영역과 경계를 표현(예: 건물, 농업구역 등)

      • 연속된 선으로 둘러싸인 2차원 객체로 크기와 둘레 정보를 가질 수 있음

        ⚠️ Polygon은 반드시 폐합된 다각형이어야 함


  • 벡터 데이터의 파일 형식

    • Shapefile 형식

      • ESRI에서 개발한 벡터 데이터 파일 포맷으로 많은 GIS 소프트웨어에서 실질적 표준으로 사용되어 왔음

      • 공간데이터를 구성하는 각각의 파일 크기는 최대 2GB로 제한

      • 속성 테이블의 필드 이름은 최대 10자를 넘을 수 없고, 필드 수도 255개 이내로 제한

      • 속성 테이블에서 값이 없음(null)은 0으로 기록됨

좌표계와 SRID

1. 좌표체계의 개념

  • 좌표체계의 필요성

    • 모든 공간정보 자료는 정확한 위치를 가지고 있어야 함

    • 좌표 정보를 이용해 임의의 점이 지표 위 어느 지점에 위치해 있는지 표현 가능

      • 좌표의 원점, 거리 단위, 방향 등의 정보 필요

  • 좌표체계의 개요

    • 어떤 점의 위치를 설명하기 위한 규정의 집합

    • 한 점의 위치를 표현하기 위해 사용

    • 사용하는 좌표체계에 따라 좌표 값이 달라짐

      • 사용하는 자료의 좌표계를 정확히 알지 못하면 동일한 대상물이 서로 다른 곳에 표시되는 문제점 발생

  • 좌표체계의 개념

    • 지표 상의 위치를 정의하기 위한 기준 프레임

    • 지리좌표체계(Geographic Coordinate System)

      • 3차원의 구면을 이용하는 좌표계

      • 경도(Longitude)와 위도(Latitude) 값으로 위치 지정

      • 지구 중심에서 지표면 상에 지점까지 측정된 각

    • 투영좌표체계(Projected Coordinate System)

      • 지리좌표를 평면 상에 투영한 좌표계

      • 하나의 타원체를 투영하는데 다양한 방식의 투영법 존재

2. 지리좌표체계(Geographic Coordinate System)

  • 지오이드(Geoid)

    • 실제 지구모양에 가깝도록 나타낸 것

    • 평균해수면을 육지까지 연장한 가상적인 면

    • 중력 방향에 수직인 (등)포텐셜면

    • 지구 상에서 높이를 측정하는 기준이 되는 면

  • 타원체(Ellipse)

    • 지구타원체

      • 지구 모양과 가장 비슷한 형상을 가지고 있는 타원체

    • 준거타원체

      • 어느 지역의 측지측량계의 기준이 되는 타원체

    • 국제표준타원체

      • 전 세계적으로 측지측량계를 통일하기 위한 지구 타원체

  • 지리좌표체계

    • 3차원의 구면을 이용하는 좌표계

3. 투영좌표체계(Projected Coordinate System)

  • 투영(Projection)

    • 3차원의 타원체에 그려진 경위도 선을 평면(2차원)의 지도에 나타낼 수 있도록 체계적으로 변환하는 것

    • 지표면(3차원)에 위치한 객체의 형상과 면적, 거리, 방향 등을 2차원의 지도에서 그대로 정확하게 나타내는 것은 불가능

    • 지도 제작 시에 고려해야 하는 요소

      • 정형성: 지도 상에서의 모양이 지표면 상의 실제 모양과 동일한가?

      • 정적성: 지도 상에서의 면적이 지표면 상의 실제 면적과 같은 비례로 나타나는가?

      • 정거성: 지도 상에서 두 지점들 간의 거리가 지표면과 같은 관계를 유지하는가?

    • 지구본과 같은 3차원의 구체(또는 타원체)를 평면으로 투영하게 되면 이러한 특성이 왜곡되어 나타남

  • 투영법

    • 3차원인 지구를 2차원 평면으로 펼칠 때 어떤 기하학적 곡면(투영면)을 사용하는 지에 따라 분류

    • 원통도법(Cylindrical Projection)

      • 적구나 특정 표준위선을 따라 지구를 둘러싼 원통면에 투영한 뒤 펼침

      • 대표적인 예: 메르카토르, TM(횡축 메르카토르), UTM

    • 원추도법(Conic Projection)

      • 지구본 위에 원뿔을 씌운 형태로 투영한 뒤 펼침

      • 대표적인 예: 람베르트 정각원추, 알버스 정적원추

    • 방위도법(Azimuthal / Planar Projection)

      • 지구의 한 점(주로 극지방이나 특정 지점)에 평면을 접하게 하여 투영

      • 대표적인 예: 정거방위, 정사, 평사, 심사

  • 평면직각 좌표계

    • 평면의 2차원상에서 공간정보의 위치를 표현하기 위한 방법

    • 좌푯값이 양수와 음수 모두 가질 수 있으므로 경우에 따라 가산값을 부여하여 양수화

PostGIS와 공간 데이터베이스

1. 공간 자료의 특징

  • 비정형성

    • 각 공간 개체의 내용 및 구조가 개체 형식에 따라 다르게 표현

    • 같은 형식 간에도 점의 개수 및 서브 개체의 개수 등에 의하여 다른 형태와 길이를 가짐

  • 대용량성

    • 일부 공간데이터의 경우 DBMS의 한 페이지를 넘는 크기를 가질 수 있음

2. 공간데이터베이스의 특성

  • 자료의 크기와 복잡성

    • 공간 데이터는 위치 정보를 갖는 도형자료와 그 도형의 특성을 나타내는 속성정보로 구성

    • 자료의 양이 클뿐만 아니라 위상 정보를 갖는 만큼 자료의 구조도 복잡함

  • 공간 전용 질의 및 인덱싱

    • 일반 데이터베이스에서 다루지 않는 공간 형식의 데이터를 처리하므로 이에 적합한 함수가 존재

    • 이를 이용한 공간 전용 질의가 가능하며, 질의 효율을 높이기 위한 공간 전용 인덱싱 기법이 적용

      • 현재 위치에서 가장 가까운 병원은 어디인가?

      • 서울특별시의 면적은 얼마인가?

      • 서울특별시를 지나는 도로의 길이는 몇 km인가?

3. 공간데이터베이스의 구성 요소

  • 구성요소

    • 공간 데이터 모델, 공간 참조 시스템, 공간 데이터 전용 질의, 공간 인덱스

  • 공간 전용 질의

    • SQL을 이용하는 방식과 거의 동일하게 공간 질의어를 이용 가능

    • 공간 질의의 종류는 데이터 정의어(DDL)와 공간 데이터 관련 함수로 구성

    • 데이터 정의어를 이용한 공간 질의

      • 테이블을 생성하고, 인덱스를 생성하는 부분은 일반 데이터베이스와 동일하지만, GEOMETRY 형식의 컬럼 생성

      • GEOMETRY 칼럼에는 점, 선, 면 등으로 정의된 데이터 모델을 따르는 공간 데이터가 저장

    • 공간 데이터 관련 함수

      • SELECT, INSERT, UPDATE, DELETE 등의 질의를 수행할 때 공간 데이터는 공간 함수와 같이 쓰는 경우가 대부분

      • 공간 데이터 변환, 좌표 변환, 면적 계산, 거리 계산, 인접한 개체 탐색 등 공간 데이터와 관련된 수 많은 함수를 공간 데이터베이스에서 지원

  • 공간 인덱스

    • 공간 데이터 전용 질의를 수행하기 위해서는 효율적으로 데이터에 접근할 수 있는 기법 필요

    • 저장된 많은 양의 공간 데이터에 대하여 실제 처리해야 할 개체의 집합을 줄이는 효율적인 공간 접근 방법(Spatial Access Method, SAM) 개발

      • 공간 접근 방법: 공간 인덱스를 사용하여 공간 질의에 대하여 처리될 개체의 수를 줄이고자 하는 방법

4. PostGIS 소개

  • PostGIS란

    • PostgreSQL의 공간 기능을 추가하는 확장(Extension)

    • PostgreSQL이 공간데이터베이스의 역할을 할 수 있도록 해주며 다양한 장점을 가짐

      • 다양한 공간 함수와 연산 제공, 복잡한 쿼리와 분석 지원, 대규모 데이터셋에서도 높은 성능

    • 공간데이터베이스의 세 가지 핵심 요소(공간 형식, 공간 인덱스, 공간 함수)를 PostgreSQL에 추가

      • 공간 자료형: geometry(평면), geography(구면, 위경도 기반), raster

      • 공간 함수 : 300개 이상 (ST_로 시작)

      • 공간 인덱스: GiST 인덱스로 빠른 검색

      • 좌표계 변환: 수천 개 좌표계 내장

지오메트리 생성 함수

1. 기하 데이터의 이해

  • 기하 데이터의 개념

    • 공간객체를 표현하는 점, 선, 면을 도형(geometry)이라 부름
    • 벡터 데이터에 대한 위치, 면적, 길이 등 특성 정보 추출 가능

  • 기하 데이터의 종류

    • OpenGIS(OGC) 표준 사양을 기반으로 다양한 공간 기하 데이터 타입을 지원

      • 크게 기본(단일) 도형, 멀티(복합) 도형, 곡선이 포함된 도형, 3차원/ 복합 구조체 등으로 구분

    • 기본 기하 데이터 타입(Single Geometries)

      • 점(Point): 공간 상의 단일 지점 좌표(X, Y)

      • 선(LineString): 두 개 이상의 점이 연결된 연속된 선

      • 면(Polygon): 폐합된 형태를 가지는 다각형

    • 멀티 기하 데이터 타입(Multi-Geometries)

      • 멀티 점(MultiPoint): 여러 개의 점을 하나의 단위로 묶은 것

      • 멀티 선(MultiLineString): 여러 개의 선을 하나의 단위로 묶은 것

      • 멀티 면(MultiPolygon): 여러 개의 폴리곤을 하나의 단위로 묶은 것

    Polygon과 Multipolygon은 하나의 객체(feature)가 몇 개의 독립된 영역으로 이루어져 있는가로 구분

2. 기하 데이터의 표기법

  • 표준 방법

    • WKT(Well-Known Text)
      • 공간 객체를 미리 정의된 형식의 문자열로 나타내는 것

    ※ 예시
     - 좌표가 (0,0)인 점 데이터: POINT
     - (0, 0)(0,0), (1,1), (2,2) 세 점을 연결한 선 데이터: LINESTRING(0 0, 1 1, 2 2)
     - 내부에 빈 공간을 포함하는 면 데이터: POLYGON((0 0, 4 0, 4 4, 0 0), (1 1, 2 1, 1 2, 1 1))
     - 두 점의 집합: MULTIPOINT(0 0, 1 2)
     - 점과 선의 집합: GEOMETRYCOLLECTION(POINT(2 3), LINESTRING(2 3, 3 4))

    • WKB(Well-Known Binary)
      • 공간 객체를 미리 정의된 형식의 바이너리(16진수)로 나타내는 것

    ※ 예시
     POINT(2 4): 000000000140000000000000004010000000000000
      - 00: 바이트 배열 순서를 정의하는 값
      - 00000001: 데이터의 종류가 POINT 데이터라는 것을 정의하는 값
      - 4000000000000000: 점의 X좌표가 2라는 것을 의미하는 값
      - 4010000000000000: 점의 Y좌표가 4라는 것을 의미하는 값

3. 기하 데이터 생성함수

  • 💻 ST_MakePoint

    • 좌표(x, y)를 입력받아 점 데이터를 생성하는 함수

    • 실수형(double)의 X, Y 좌표값을 ,로 구분하여 입력

    ST_MakePoint만으로는 SRID가 0이라 좌표계를 별도로 선언해야 함

    SELECT ST_MakePoint(127.289, 36.480);
SELECT ST_MakePoint(127.262, 36.502);

  • 💻 ST_MakeLine

    • 점을 입력받아 선 데이터를 생성하는 함수

    • 선 데이터는 점으로 구성되기 때문에 점의 집합으로 입력

    SELECT ST_MakeLine(
    ST_MakePoint(127.261, 36.504), 
    ST_MakePoint(127.260, 36.502)
    );

  • 💻 ST_MakeEnvelope

    • 좌표(x, y)를 입력받아 면(다각형) 데이터를 생성하는 함수

    • 가장 작은 좌표(좌측 하단 xmin, ymin)와 가장 큰 좌표(우측 상단 xmax, ymax)를 입력

    SELECT ST_MakeEnvelope(
    0, 0, 100, 50
    );

  • 💻 ST_GeomFromText

    • WKT 형태로 지정된 기하 데이터를 geometry 형식의 기하 데이터로 변환해 주는 함수

    • 두 번째 인자는 SRID, 생략하면 SRID = 0(미지정)

    WKT는 쉼표로 점을 구분, 한 점의 X와 Y는 공백으로 구분

    SELECT ST_GeomFromText('POINT(127.289 36.480)', 4326);
SELECT ST_GeomFromText('LINESTRING(127.261 36.504, 127.260 36.502)', 4326);
SELECT ST_GeomFromText('POLYGON((127.268 36.499, 127.268 36.499, 127.268 36.498, 127.267 36.498, 127.268 36.499))', 4326);

좌표계 함수

1. 함수 종류

  • 좌표계를 조회 · 선언 · 변환하는 함수를 구분해서 사용해야 함
함수기능비고
ST_SRID(g)현재 SRID를 읽기좌표값 확인
ST_SetSRID(g, srid)SRID 라벨을 다시 붙이기좌표값 설정
ST_Transform(g, srid)다른 좌표계로 좌표를 실제 변환좌표값이 바뀜

2. 함수별 사용법

  • 💻 ST_SRID

    • 기하 데이터의 좌표계 정보를 확인하는 함수
    -- 생성되어 있는 모든 기하 데이터의 좌표계 번호 출력
SELECT * FROM geometry_columns;

-- 기하 데이터의 모든 객체에 대한 좌표계 번호 출력
SELECT ST_SRID(geom) FROM park LIMIT 1;

  • 💻 ST_SetSRID

    • 기하 데이터의 좌표계를 정의하는 함수
    -- 기하 데이터 생성 시 SRID를 입력하지 않으면 0
SELECT ST_MakePoint(127.289, 36.480);

-- 기하 데이터 생성하고 ST_SetSRID로 좌표계 설정
SELECT ST_SetSRID(ST_MakePoint(127.289, 36.480), 4326);

--- 간단버전
SELECT ST_Point(127.289, 36.480, 4326);

  • 💻 ST_Transform

    • 기하 데이터의 원본 좌표계를 다른 좌표계로 변환하는 함수
    --- 기하 데이터 생성 시 좌표계 설정하고 변환 가능
SELECT ST_Transform(ST_SetSRID(ST_MakePoint(127.289, 36.480), 4326), 5186));

--- 생성되어 있는 테이블에서 좌표계 변환 시 주의 필요
SELECT ST_Transform(location, 3857) FROM ex_01;
SELECT ST_SRID(location) FROM ex_01

--- ALTER TABLE은 이미 생성된 테이블의 구조를 변경할 때 사용
--- 컬럼을 추가, 삭제, 수정하거나 제약 조건을 변경 가능
ALTER TABLE ex_01
    ALTER COLUMN location TYPE geometry(MULTIPOINT, 3857)
    USING ST_Transform(location, 3857);
SELECT ST_SRID(location) FROM ex_01;

--- 원본은 보존하고 새로운 테이블을 만들 때 
CREATE TABLE ex_01_re AS
SELECT name, ST_Transform(location, 4326)::geometry(MULTIPOINT, 4326) AS geom FROM ex_01;

--- 좌표계 정보 확인
SELECT ST_SetSRID(geom) FROM ex_01_re

  • 거리 측정 방식

    • Euclidean 거리: 직선거리, 피타고라스 정리 이용

    • Manhattan 거리: 직각거리

    • Minkowski 거리: p라는 계수를 통해 조정한 거리

    • Network 거리: 실제 도로망, 수계망 등을 포함한 네트워크 상에서 두 지점을 연결하는 최소거리/시간

  • 측지학(Geodesic) 거리

    • 구면 위에서 직선의 구실을 하는 두 지점 사이의 거리(지오이드 상에서의 거리)

    • 측지학 거리가 평면(planar) 방식보다 일정한 크기를 가짐

  • 가우스(Gauss) 면적 공식

    • 좌표평면 상에서 꼭지점의 좌표를 알 때 다각형의 면적을 구할 수 있는 방법

2. 함수 종류

  • 기하 데이터가 가지고 있는 형상 정보를 바탕으로 위치정보, 면적, 길이 등을 계산

  • 기하 데이터에 설정되어 있는 좌표계에 따라 결과값의 단위가 결정

  • 미터 단위의 결과 값이 필요하다면 적정한 투영좌표계로의 변환 필요

함수대상단위
ST_X(g), ST_Y(g)점좌표계 단위

공간관계 함수

1. 공간 데이터 위상

  • 공간 데이터 위상의 개념

    • 도형 자료에서 서로 연결된 또는 인접한 객체들 사이의 공간적 상호관계(인접성, 연결성, 근접성 등)

    • 객체들 간의 위상 관계를 바탕으로 일정 조건을 만족하는 지역이나 조건을 검색, 분석이 가능

  • 공간질의에 사용되는 기초적인 공간 관계

  • 공간 관계 함수의 이해

    • 다각형은 건물, 빗금 친 구역은 산사태 발생 지역

    • 산사태 발생 지역에 교차되는 건물 개수는?

    • 산사태 발생 지역과 중첩되는 건물 개수는?

    • 산사태 발생 지역과 맛닿아 있는 건물 개수는?

    • 건물에 산사태 발생 지역이 완전히 포함되는 건물 개수는?

2. 함수 종류

함수한 줄 의미직관
ST_Intersects(a,b)조금이라도 닿거나 겹친다가장 넓은 “관련 있음”
ST_Disjoint(a,b)전혀 만나지 않는다Intersects의 반대
ST_Contains(a,b)a가 b를 완전히 포함a ⊃ b
ST_Within(a,b)a가 b 안에 있다a ⊂ b (Contains의 반대 방향)
ST_Touches(a,b)경계만 닿는다(내부는 안 겹침)이웃한 필지
ST_Overlaps(a,b)같은 종류의 도형이 일부만 겹침부분 겹침
ST_Crosses(a,b)선이 면(또는 선)을 가로지른다도로가 구역을 통과
ST_DWithin(a,b,d)거리 d 이내에 있다“반경 d m 안”
ST_Buffer(g, d)g에서 d만큼 확장한 면반경 분석, 영향권

✅ ST_Contains(a,b) = ST_Within(b,a) : 인자 순서가 바뀐 관계

3. 함수별 사용법

  • QGIS와 병행 실습

    • 메뉴에서 벡터 > 조사도구 > 위치로 선택을 실행하여 공간적 위치 관계로 질의 실습

      • 다음 위치에서 피처 선택: 선택하고자 하는 객체가 있는 레이어

      • 피처 위치: 선택 조건 선택

      • 다음과 같은 피처를 비교: 선택 조건으로 비교하고자 하는 대상 레이어

  • 💻 ST_Intersects

    • 입력 받은 기하 데이터에서 교차하는 객체를 추출
    --- 공간관계 함수는 Geometry 형식의 필드를 이용해서 계산
SELECT * FROM yang_building as b, yang_flood as f
--- 건물과 침수구역이 조금이라도 닿거나 겹치는 객체 추출
WHERE f.id='1' and ST_Intersects(b.geom, f.geom);

  • 💻 ST_Disjoint

  • - 입력 받은 기하 데이터에서 연산대상 객체에 **해당하지 않는** 객체를 추출

    --- 공간관계 함수는 Geometry 형식의 필드를 이용해서 계산
SELECT * FROM yang_building as b, yang_flood as f
--- 건물과 침수구역이 전혀 겹치지 않는 객체 추출
WHERE f.id='1' and ST_Disjoint(b.geom, f.geom);

  • 💻 ST_Contains

    • 입력 받은 기하 데이터가 연산대상 객체를 완전히 포함하는 객체를 추출
    --- 공간관계 함수는 Geometry 형식의 필드를 이용해서 계산
SELECT * FROM yang_building as b, yang_flood as f
--- 건물이 침수구역을 완전히 포함하는 객체 추출
WHERE f.id='1' and ST_Contains(b.geom, f.geom);

  • 💻 ST_Within

    • 입력 받은 기하 데이터가 연산 대상 객체 내에 완벽히 포함되는 객체를 추출
    --- 공간관계 함수는 Geometry 형식의 필드를 이용해서 계산
SELECT * FROM yang_building as b, yang_flood as f
--- 건물이 침수구역 안에 있는 객체 추출
WHERE f.id='1' and ST_Within(b.geom, f.geom);

  • 💻 ST_Overlaps

    • 입력 받은 기하 데이터에서 연산대상 객체를 포함하는 객체를 추출
    --- 공간관계 함수는 Geometry 형식의 필드를 이용해서 계산
SELECT * FROM yang_building as b, yang_flood as f
--- 건물과 침수구역이 일추만 겹치는 객체 추출
WHERE f.id='1' and ST_Overlaps(b.geom, f.geom);

  • 💻 ST_DWithin

    • 입력 받은 기하 데이터에서 지정된 거리 내에 있는 객체를 추출
    --- 공간관계 함수는 Geometry 형식의 필드를 이용해서 계산
SELECT * FROM yang_building as b, yang_flood as f
--- 침수구역에서 500m 이내에 위치한 건물 객체
WHERE f.id='1' and ST_DWithin(b.geom, f.geom, 500);

  • 💻 ST_Buffer

    • 입력 받은 기하 데이터에서 특정 거리 내에 있는 객체를 추출
    --- 공간관계 함수는 Geometry 형식의 필드를 이용해서 계산
SELECT * FROM yang_building as b, yang_flood as f
--- 침수구역에서 500m 이내에 위치한 건물 객체
WHERE ST_Intersects(b.geom, ST_Buffer(f.geom, 500));

    • 두 테이블을 조인한 후 소유구분명별로 토지가 총 몇 필지(개수)가 있는지 집계하고, 필지 수가 많은 순서대로 내림차순 정렬

💻 레이어별 좌표계 점검

  • 모든 레이어의 좌표계를 확인한 후, 좌표계가 다르다면 EPSG:5186으로 변환하여 좌표계를 통일해 봅시다.

    • 💡 HINT! ALTER TABLE, ST_SRID, ST_Transform

    정답 
    
  /* 생성되어 있는 모든 기하 데이터의 좌표계 번호 출력 */
  SELECT * FROM geometry_columns;    
  /* ALTER TABLE로 hospital 테이블의 구조 변경 */
  ALTER TABLE hospital
  ALTER COLUMN geom TYPE geometry(POINT, 5186) 
  USING ST_TRANSFORM(geom, 5186);
  /* 좌표계 변경되었는지 결과 확인 */
  SELECT ST_SRID(geom) FROM hospital LIMIT 1;
  /* ALTER TABLE로 park 테이블의 구조 변경 */
  ALTER TABLE park
  ALTER COLUMN geom TYPE geometry(POINT, 5186) 
  USING ST_TRANSFORM(geom, 5186);
  /* 좌표계 변경되었는지 결과 확인 */

  /* ALTER TABLE로 road 테이블의 구조 변경 */
  ALTER TABLE road
  ALTER COLUMN geom TYPE geometry(Multilinestring, 5186) 
  USING ST_TRANSFORM(geom, 5186);
  /* 좌표계 변경되었는지 결과 확인 */
  SELECT ST_SRID(geom) FROM road LIMIT 1;
  /* 생성되어 있는 모든 기하 데이터의 좌표계 번호 재출력 */
  SELECT * FROM geometry_columns;

⚠️ SetSRID와 Transfrom의 구분

  • 좌표계 변환 대신 라벨만 바꾸면 어떤 일이 생기는지 확인하고, SetSRID와 Tranform의 차이를 꼭 기억합시다!

-- 1) 소방서를 4326으로 변환한 연습용 테이블
CREATE TABLE fire_4326 AS
SELECT 서센터명, ST_Transform(geom, 4326) AS geom FROM fire;

-- 2) 서로 다른 SRID 연산 → 오류 발생을 확인
SELECT ST_Distance(h.geom, f.geom)
FROM hospital AS h, fire_4326 AS f
LIMIT 1;

-- 3) 올바른 해결: 좌표를 실제로 변환
SELECT ST_Distance(h.geom, ST_Transform(f.geom, 5186)) AS dist_m
FROM hospital AS h, fire_4326 AS f
LIMIT 1;

-- 4) 잘못된 해결: 라벨만 5186으로 바꿈 → 거리 값이 엉뚱함
SELECT round(ST_Distance(h.geom, ST_SetSRID(f.geom, 5186))) AS wrong_dist_m
FROM hospital h, fire_4326 f
LIMIT 1;

-- 5) 정리
DROP TABLE fire_4326;

B. 공간관계 함수 비교: 같은 대상을 여러 관계 함수로 비교해 차이를 확인

💻 공간조인 활용

  • 영업 중인 병원이 많은 동 TOP 10은 어디인지 조회해 봅시다.

    • 💡 HINT! JOIN, GROUP BY

    정답 
    
  SELECT 동이름, count(*) AS 병원개수
  FROM hospital AS h
  /* 병원과 동 레이어를 공간 조인하고 ST_Within 활용 */
  JOIN dong AS d ON ST_Within(h.geom, d.geom)
  WHERE h.영업상태명 = '영업/정상'
  GROUP BY d.동코드, d.동이름
  ORDER BY 병원개수 DESC
  LIMIT 10;

💻 Within vs Intersect

  • 병원-동 조인 결과 수를 두 함수로 비교하고 전체 병원 수와도 비교해 봅시다.

    • 💡 HINT! ST_Within, ST_Intersect

    정답 
    
  SELECT
      /* 전체 병원 수 계산 */    
      (SELECT count(*) FROM hospital) AS total_hosp,
      /* ST_Within으로 계산한 병원 수 */
      (SELECT count(*) FROM hospital AS h 
	        JOIN dong AS d ON ST_Within(h.geom, d.geom)) AS within_cnt,
      /* ST_Intersects로 계산한 병원 수 */
      (SELECT count(*) FROM hospital AS h 
	        JOIN dong AS d ON ST_Intersects(h.geom, d.geom)) AS intersects_cnt;

💻 Contains vs Intersects

  • 동 안에 완전히 포함되는 공원 수, 걸치기만 해도 포함되는 공원 수를 계산하여 비교해 봅시다.

    • 💡 HINT! ST_Contains, ST_Intersects

    정답 
    
  SELECT d.동이름,
     /* ST_Contains를 이용해 동 안에 완전히 포함되는 공원 수 계산 */
     count(*) FILTER (WHERE ST_Contains(d.geom, p.geom)) AS fully_inside,
     count(*) AS intersects_cnt
  FROM dong d
  /* ST_Intersects를 이용해 걸치기만 해도 포함되는 공원 수 계산 */
  JOIN park p ON ST_Intersects(d.geom, p.geom)
  GROUP BY d.동코드, d.동이름
  ORDER BY intersects_cnt DESC
  LIMIT 10;

💻 Touches

  • 강남구와 경계가 맞닿아 있는 구는 어디인지 조회해 봅시다.

    • 💡 HINT! ST_Touches

    정답 
    
  /* b는 기준이 되는 강남구, a는 강남구와 인접한 다른 자치구 */
  SELECT a.A2 AS neighbor
  FROM sigungu AS a
  JOIN sigungu AS b
      ON ST_Touches(a.geom, b.geom)
  WHERE b.A2 LIKE '%강남구'
      AND a.A2 NOT LIKE '%강남구';

💻 Crosses

  • 종로3가에 닿는 도로 구간 중 동 안에 완전히 있는 구간 수, 동 경계를 가로질러 밖으로 나가는 구간 수를 확인해 봅시다.

    • 💡 HINT! ST_Within, ST_Crosses

    정답 
    
  /* 동 안에 완전히 있는 구간 수를 ST_Within으로 계산 후 count로 집계 */
  SELECT count(*) FILTER (WHERE ST_Within(r.geom, d.geom)) AS inside_roads,
  /* 동 경계를 가로질러 밖으로 나가는 구간 수를 ST_Crosses로 계산 후 count로 집계 */
         count(*) FILTER (WHERE ST_Crosses(r.geom, d.geom)) AS crossing_roads
  FROM dong AS d
  JOIN road AS r ON ST_Intersects(r.geom, d.geom)
  WHERE d.동이름 = '종로3가';

💻 Within VS Overlaps VS Touches

  • 신당동에 있는 건물이 자기 필지 안에 있는지, 필지 경계를 침범하는지, 이웃 필지에 닿기만 하는지를 확인하여 건물의 개수를 조회해 봅시다.

    • 💡 HINT! ST_Within, ST_Overlaps, ST_Touches

    정답 
    
  /* 건물이 자기 필지 안에 있는지를 ST_Within으로 계산 후 count로 집계 */
  SELECT count(*) FILTER (WHERE ST_Within(b.geom, c.geom)) AS inside_parcel,
  /* 건물이 자기 필지 경계를 침범하는지를 ST_Overlaps로 계산 후 count로 집계 */
         count(*) FILTER (WHERE ST_Overlaps(b.geom, c.geom)) AS straddle_parcel,
  /* 건물이 이웃 필지에 닿기만 하는지를 ST_Touches로 계산 후 count로 집계 */
         count(*) FILTER (WHERE ST_Touches(b.geom, c.geom))  AS touch_only
  FROM building b
  JOIN cadestral c ON ST_Intersects(b.geom, c.geom)
  WHERE b.법정동명 LIKE '%신당동';

💻 병원이 없는 동

  • 영업 중인 병원이 하나도 없는 동은 어디인지를 조회해 봅시다.

    정답 
    
  SELECT d.동이름
  FROM dong AS d
  WHERE NOT EXISTS (
  SELECT 1 
  FROM hospital h 
  WHERE ST_Within(h.geom, d.geom) 
    AND h.영업상태명 = '영업/정상'

💻 소방 사각지대

  • 동을 기준으로 반경 1km 이내에 소방서가 하나도 없는 동을 찾고 이름 순으로 정렬해 봅시다.

    정답 
    
  SELECT d.동코드, d.동이름
  FROM dong AS d
  WHERE NOT EXISTS (
      SELECT 1 
      FROM fire AS f 
      WHERE ST_DWithin(d.geom, f.geom, 1000))

💻 병원 50m 안의 공원

  • 병원별로 반경 500m 안의 공원 수를 ST_DWithin으로 구하고, ST_Buffer로 같은 결과가 나오는지 확인해 봅시다.

    • 💡 HINT! ST_DWithin, ST_Buffer

    정답 
    
  SELECT h.사업장명, h.도로명주소, 
      (SELECT count(*) FROM park AS p 
          WHERE ST_DWithin(h.geom, p.geom, 500)) AS parks_500
  FROM hospital AS h
  WHERE h.영업상태명 = '영업/정상'
  ORDER BY parks_500 DESC
  LIMIT 10;
  SELECT
      (SELECT count(*) FROM hospital AS h 
	        JOIN park AS p ON ST_DWithin(h.geom, p.geom, 500)) AS dwithin_cnt,
      (SELECT count(*) FROM hospital AS h 
	        JOIN park AS p ON ST_Intersects(ST_Buffer(h.geom, 500), p.geom)) AS buffer_cnt;

💻 건물과 토지소유자

  • 건물이 있는 필지의 소유구분별 건물 수와 건물 면적의 합계를 조회해 봅시다.

    • 💡 HINT! ST_AREA, JOIN

    정답 
    
  SELECT o.소유구분명,
     count(*) AS bld_cnt,
     sum(ST_Area(b.geom)) AS area
  FROM building AS b
  JOIN owner AS o ON b.pnu = o.pnu
  GROUP BY o.소유구분명
  ORDER BY bld_cnt DESC;

💻 소방서 500m 안의 도로

  • 소방서별로 반경 300m 안에 걸치는 도로 구간 수, 구간 길이 합(km), 최고 제한속도를 조회해 봅시다.

    • 💡 HINT! SUM, MAX, ST_Length, ST_DWithin, 공간조인

    정답 
    
  SELECT f.서센터명,
     count(*) AS segments,
     (sum(ST_Length(r.geom)) / 1000) AS length,
     max(r.max_spd) AS max_speed
  FROM fire AS f
  JOIN road AS r ON ST_DWithin(f.geom, r.geom, 500)
  GROUP BY f.서센터명
  ORDER BY length DESC
  LIMIT 10;

💻 공간 + 일반조인

  • 어린이 대공원 300m 이내 필지의 소유구분별 필지의 수를 조회해 봅시다.

    • 💡 HINT!

  SELECT o.소유구분명, count(DISTINCT c.pnu) AS parcels
  FROM park AS p
  JOIN cadestral AS c ON ST_DWithin(c.geom, p.geom, 300)
  JOIN owner AS o ON o.pnu = c.pnu                      
  WHERE p.공원명 = '어린이대공원'

도전 1. 🚨 고층 건물의 안전 사각지대 ⭐⭐⭐

  • 질문: 지상 5층 이상이면서 ① 소방서 2km 밖 ② 영업 중인 병원 1km 밖인 건물을 층수 높은 순으로 20개 구하시오.

    • 출력 컬럼: 건물명, 법정동명, 지상층수, 높이 -💡HINT: ST_DWithin, NOT EXISTS

정답 
CREATE TABLE Challenge_01 AS
SELECT b.건물명, b.법정동명, b.지상층수, b.높이
FROM building AS b
WHERE b.지상층수 >= 5
  AND NOT EXISTS (SELECT 1 FROM fire AS f
                  WHERE ST_DWithin(b.geom, f.geom, 2000))
  AND NOT EXISTS (SELECT 1 FROM hospital AS h
                  WHERE h.영업상태명 = '영업/정상' AND ST_DWithin(b.geom, h.geom, 1000))

도전 2. 🌳 큰 공원 주변 건물 ⭐⭐⭐⭐

  • 질문: 면적 상위 3개 공원에 대해 반경 300m 안의 건물 수와 연면적 합계를 구하시오.

    • 테이블 이름: Challenge_02

    • 출력 컬럼: 공원명, 건물수는 bld_cnt, 연면적 합계는 total_floor_area

    • 💡HINT: ST_Area, ST_Dwithin, 서브쿼리

정답 
CREATE TABLE Challenge_02 AS
SELECT p.공원명,
       count(*) AS bld_cnt,
       sum(b.연면적) AS total_floor_area
FROM (SELECT 공원명, geom
      FROM park
      ORDER BY ST_Area(geom) DESC
      LIMIT 3) AS p
JOIN building AS b ON ST_DWithin(p.geom, b.geom, 300)
GROUP BY p.공원명
ORDER BY bld_cnt DESC;

    • 지상, 지하, 수상, 수중 등 공간 상에 존재하는 자연 또는 인공적인 객체에 대한 위치정보 및 이와 관련된 공간적 인지와 의사결정에 필요한 정보(공간정보산업 진흥법)

  • 지리정보시스템(Geographic Information System, GIS)

    • 공간적 문제를 해결하기 위해 다양한 공간자료를 수집, 구축, 유지, 관리, 편집하고 분석과 모델링을 통해 추출된 고부가가치의 정보를 표현하고 출력할 수 있게 고안된 종합적인 정보처리시스템

  • 어플리케이션별 GIS 분류

    • 웹(Web) GIS

      • 인터넷 기술과 GIS를 접목하여 공간정보의 입력, 수정, 조작, 출력 등 GIS 데이터와 서비스를 인터넷 환경에서 제공

    • 모바일(Mobile) GIS

      • 언제 어느 장소에서나 공간정보에 기반한 유무선 환경의 통신망을 통해 현재 위치 기반의 필요 정보를 제공할 수 있도록 구현된 GIS

    • 엔터프라이즈(Enterprise) GIS

      • 특정한 업무부서가 아닌 기업이나 기관 전체에서 필요로 하는 정보를 제공하는 것을 목적으로 지리정보를 효율적으로 관리, 분석, 활용하기 위한 GIS

2. 웹 GIS 개념 및 특징

  • 웹 GIS 개념

    • 인터넷을 통하여 단일 또는 다수의 기존 애플리케이션 시스템을 표준화된 기술로 결합시켜 모든 비즈니스를 가능하게 하는 웹 서비스를 기반으로 한 개념

    • 인터넷을 통하여 공간데이터를 교환하고 전송할 뿐 아니라 검색, 분석, 처리할 수 있는 시스템

  • 웹 GIS 특징

    • 분산 환경

      • 대용량을 처리해야 하는 GIS의 기능으로 인하여 분산 컴퓨팅 환경(Distributed Computing Environment, DCE)을 취함

      • 인터넷으로 연결된 수많은 서버에 분산되어 있는 데이터와 기능의 객체를 사용자 요구에 따라 다양한 기능을 수행해야 함

    • 대화형 시스템

      • 인터넷에서 GIS 분석 기능을 수행하는 데 클라이언트 서버 개념을 응용

      • 벡터를 따로 처리할 수 있는 클라이언트를 개발하고 이를 웹 상에 내재시켜 대화형 시스템을 구현

    • 동적 유지 관리

      • 분산 시스템으로써 데이터와 소프트웨어를 최신의 정보로 유지할 수 있음

    • 통합 정보 제공

      • 월드 와이드 웹은 웹 GIS에 비디오, 오디오, 지도, 텍스트, 방송 등의 다양한 형태의 자료를 동일한 웹 페이지로 통합할 수 있는 기능을 제공

    • 다양한 사용자들과 협업 가능

      • 다양한 유형의 지리정보 데이터를 서비스 및 데이터 형태인 단순화된 모델로 통합하여 플랫폼에 저장

      • 이러한 공통된 모델을 통해 개인, 기관, 커뮤니티 등 모든 사용자를 연결하여 동일한 정보에 접근 가능

    • 독립적 크로스 플랫폼(cross platform)

      • 기종이나 운영체제에 독립적인 시스템으로 클라이언트의 하드웨어, 운영체제 및 관계형 데이터베이스 시스템의 종류에 관계없이 공통의 데이터와 기능을 공유할 수 있는 크로스 플랫폼을 지원

    • 상호운용성(interoperability)

      • GIS 프로그램을 소유하지 않아도 웹상에서 GIS 프로그램을 구동하는 것과 같은 기능을 수행

      • 데이터 포맷, 데이터 교환, 데이터 접근에 대한 표준 및 GIS 분석 컴포넌트의 표준 사양 등을 고려

3. 웹 서비스 표준

  • OSGeo(Open Source Geospatial Foundation)

    • 지리공간기술과 데이터의 공개 협업 개발을 지원하고 알리기 위한 비영리, 비정부 단체

    • 지리공간 분야의 오픈 소프트웨어와 오픈소스 개발을 폭넓게 재정적, 조직적, 법적으로 지원하기 위해 2006년 2월 4일 미국 시카고에서 창설

  • OGC(Open Geospatial Consortium) Standards

    • 전 세계 530곳 이상 정부기관과 기업, 대학들이 참여하고 있는 세계 최대 공간정보산업 표준화 추진 기구

    • 데이터 포맷에서부터 OGC Web Service에 이르는 다양한 표준 제정 및 인증

    • 분기당 1회씩 매년 4회의 정기총회를 개최하고, 구성 멤버는 약 40% 이상이 기업

    • 지역별 기관 수는 유럽이 208개, 북아메리카 182개, 아시아 86개, 중동 34개, 남아메리카 3개, 아프리카 3개 기관으로 구성

  • 웹 서비스 표준

    • OGC와 월드 와이드 웹 컨소시엄(World Wide Web Consortium, W3C)의 주관으로 개발

      • 웹 서비스 표준화 기구에서 진행되는 기반 기술의 표준화 작업을 바탕으로 하여 GIS와 관련되는 실질적인 기술 표준화는 OGC에서 추진

    • 웹 서비스 기반의 GIS 표준 개발을 추진하여 실제 요구에 의하여 개발해 온 다양한 표준을 개념적으로 정리 및 통합

  • OGC의 대표적인 표준 서비스

    • WMS(Web Map Service)

      • 공간 데이터베이스의 데이터를 지도 이미지로 서비스하기 위한 표준 프로토콜로 블록이나 선 같은 기본 지도(윤곽)를 표시

    • WFS(Web Feature Service)

      • 플랫폼에 독립적인 호출을 이용하여 공간데이터에 대한 개체를 요청할 수 있는 인터페이스를 제공

      • WMS가 단순한 지도 이미지만을 서비스하는 데 반하여 WFS는 공간 분석 등과 같은 연산에 필요한 데이터를 서비스

    • WPS(Web Processing Service)

      • 공간데이터에 대한 다양한 처리 서비스를 웹 상에서 정의하고 접근할 수 있도록 하기 위한 표준 프로토콜이며, 모든 OGC 표준 웹 서비스와 상호 호환성을 갖도록 함

    • WMTS(Web Map Tile Service)

      • 정적인 이미지를 모아둔 저장소를 이용하여 매우 빠르게 지도 서비스를 수행하는 서비스

      • 지도 이미지 저장소는 특정 축척별로 지도 영역을 타일 이미지로 저장한 디렉토리 구조

      • 지도를 데이터베이스로부터 직접 생성하는 것보다 훨씬 시간 단축 가능

      • 사용자가 복잡한 지도를 생성할 때 획기적으로 지도 생성 시간을 단축시키는 효과와 성능 향상을 위한 모든 노력 제거 가능

프로그래밍 개념

1. 개발자

  • 개발자가 하는 일

    • 컴퓨터가 처리할 수 있는 명령어로 코드(부호)를 작성하는 사람(코딩 또는 코더)을 지칭

      • 소스코드는 컴퓨터가 어떤 명령을 내리기 위해 컴퓨터가 이해할 수 있는 언어로 작성한 정보

    • 프로그래밍은 컴퓨터에서 작동하는 프로그램을 설계하고 개발하는 전 과정을 의미

  • 개발자가 만드는 것

    • 소프트웨어 vs 프로그램 vs 애플리케이션

      • 하드웨어: 눈에 보이고 만져지는 부분

      • 소프트웨어: 보이지 않는 부분

      • 라이브러리: 어떤 일을 수행하기 위해 필요한 기능을 일정 단위로 묶은 것

      • 프로그램: 모든 과정을 수행할 수 있도록 만든 것

      • 시스템 프로그램: 운영체제를 구성하는 소프트웨어

      • 응용 프로그램: 각각의 목적에 따라 사용자가 실행하여 활용할 수 있는 프로그램

2. 개발자의 종류

  • 개발자의 종류

    • 웹: 웹 사이트를 만드는 개발자

    • 모바일: 손 안의 앱을 만드는 개발자

    • 게임: 게임을 만드는 개발자

    • 응용 소프트웨어: 컴퓨터 프로그램을 만드는 개발자

    • 임베디드 개발자: 하드웨어를 제어하는 개발자

    • 정보보안 전문가: 컴퓨터 시스템을 보호하는 개발자

    • AI 개발자: 기계를 가르치는 개발자

  • 웹 개발자

    • 웹 사이트를 개발하는 개발자로 웹 퍼블리셔, 프론트엔드 개발자, 백엔드 개발자로 구성

  • 웹 퍼블리셔

    • 웹 사이트에서 보이는 부분을 담당하는 개발자로 해외에서는 보통 UI(User Interface) 개발자라 호칭

    • 웹 사이트의 외적 요소를 코드로 구현하는 역할을 하고 HTML, CSS, JavaScript를 사용

  • 프론트엔드 개발자(클라이언트 개발자)

    • 사용자에게 보여줄 웹 사이트 화면을 만들고 사용자의 클릭이나 드래그와 같은 동작에 따라 웹 사이트의 다양한 기능이 실행되도록 프로그래밍

    • JavaScript를 중점적으로 사용하고, 이외 TypeScript, React 라이브러리 등을 사용

  • 백엔드 개발자(서버 개발자)

    • 웹 사이트에서 눈에 보이지 않는 요소를 개발하고 화면에 들어갈 데이터를 주고받는 서버의 기능 구현

    • JavaScript, Python, PHP, JAVA 등의 언어와 각 언어별 프레임워크(framework)를 사용

    • 한국에서는 JAVA와 Spring 프레임워크 조합을 많이 사용

3. 프로그래밍 언어

  • 개발된 배경

    • 컴퓨터에 명령을 내린다는 목적으로 만들어진 언어

      • 더 많은 사람이 읽기 편한 언어

      • 짧은 코드로 더 많은 지시를 내릴 수 있는 언어

      • 보다 빨리 작동하는 언어

      • 오류로부터 안전한 언어

    • 현재는 C, 자바(JAVA), 파이썬(Python), 자바스크립트(JavaScript) 등이 대표적

  • 프로그래밍 언어의 구분

    • 추상화에 수준에 따른 분류(하드웨어 친화도)

      • 사람의 언어(자연어)에 가까울수록 고수준 언어

      • 기계의 언어(0과 1)에 가까울수록 저수준 언어

      • 어셈블리어(assembly language)는 기계어 한 줄 한 줄을 그대로 직역한 것으로 하나의 명령에 한 가지 작동

    • 실행 방식에 따른 분류

  • 통합개발환경(IDE, Integrated Development Environment)

    • 개발자들이 잘못된 코드를 작성하지 않도록 도와주는 프로그램

      • 이클립스: 자바 프로그래밍에 많이 사용되는 도구

      • 인텔리제이: 이클립스와 비슷한 용도로 사용되며, 더 강력한 기능을 가진 IDE

      • 안드로이드 스튜디오: 인텔리제이의 안드로이드 개발용 버전으로 안드로이드 앱을 만드는데 사용

      • 파이참: 파이썬 개발에 특화된 IDE

      • 엑스코드: 애플이 개발한 IDE

      • 비주얼 스튜디오: 마이크로 소프트웨어에서 제작한 IDE로 다양한 소프트웨어 개발

웹 서비스 구조

1. 웹 서비스의 개념

  • 웹 서비스의 개념

    • 웹은 서버(server)와 클라이언트(client)가 http(Hyper Text Transfer Protocol)를 통해 요청(request)과 응답(response)을 사용하여 자료를 주고받으며 정보를 교환

      • 서버(server): 정보나 서비스를 저장하고 있다가 필요한 경우 네트워크를 이용해 사용자에게 전달해 주는 컴퓨터

      • 클라이언트(client): 사용자가 원하는 정보를 서버 컴퓨터로부터 받아 오는 역할을 하는 컴퓨터

2. 프로토콜의 개념

  • 프로토콜(protocol)의 개념

    • 서버에 요청할 때 지켜야할 약속, 통신 규약이라고 함

    • HTTP(HyperText Transfer Protocol)

      • 통신 규약을 나타내는 것으로 네트워크로 이어진 두 컴퓨터가 어떤 종류의 소통을 할지 지정

      • 클라이언트의 요청과 서버의 응답으로 구성된 방식

      • 해당 웹 사이트가 신뢰할 만한 곳인지 확인하기 어려움

      • 요청과 응답 사이에 아무런 보안장치 없이 데이터가 그대로 보내짐

    • HTTPS(HTTP Secure)

      • HTTP에 보안(secure) 기능을 더한 프로토콜로 주소 창에 자물쇠 표시가 나타남

      • 클라이언트와 서버는 중요한 데이터를 보다 안전하게 주고받을 수 있음

      • 웹사이트 노출이 HTTP보다 유리함(검색엔진 최적화)

3. 웹 문서의 개념

  • 웹 문서의 개념

    • 웹에서 클라이언트가 서버에 정보를 요청하면 응답하는 콘텐츠

  • 주요 용어의 차이점

    • 웹 페이지(web page): 웹 사이트의 일부인 단일 페이지를 의미하는 것으로 홈 페이지는 웹 페이지에 포함

    • 웹 사이트(website): 여러 웹 페이지를 모아 놓은 꾸러미

    • 홈페이지(homepage): 웹 사이트의 최상위 페이지를 뜻하며 일반적으로 웹 사이트를 방문한 사용자가 가장 먼저 보게 되는 페이지

  • 웹 문서의 분류

    • 정적 웹 페이지(static web page)

      • 클라이언트가 웹 문서를 요청하면 웹 서버는 이미 만들어져 있는 문서(HTML, 이미지, JavaScript 파일 등)를 클라이언트에게 제공하는 웹 페이지

      • 사용자는 서버에 저장된 데이터가 변경되지 않는 한 고정된 웹 페이지를 계속 보게 됨

      • 모든 사용자는 같은 결과의 웹 페이지를 서버에 요청하고 응답

    • 동적 웹 페이지(dynamic web page)

      • 서버에 저장된 HTML 파일이 그대로 브라우저에 나오는 것이 아닌 동적으로 만들어지는 웹 페이지

      • 요청 정보를 처리한 후에 제작된 HTML 문서를 클라이언트에게 전송하는 웹 페이지

      • 요청에 관하여 사용자는 상황, 시간, 요청 등에 따라 다른 결과를 응답

      • 같은 페이지라도 사용자마다 다른 결과의 웹 페이지를 서버에 요청하고 받을 수 있음

    • 반응형 웹

      • 페이지 내 요소들을 신축성 있게 만들어 기기나 화면 크기에 맞게 너비나 높이, 위치 등을 자동으로 조절하는 웹 사이트

    • 적응형 웹

      • 화면 크기에 따라 PC용과 모바일용 웹사이트를 따로 만드는 것

4. 웹 사이트 구성요소

  • 웹 기술


    • HTML(HyperText Markup Language)

      • 문서나 데이터의 구조를 표현하는 데 사용되는 언어

    • CSS(Cascading Style Sheets)

      • 마크업 언어가 실제로 표시되는 방법을 기술하는 스타일 언어

    • JavaScript

      • 웹 사이트에 각종 기능을 달아주는 프로그래밍 언어

  • 웹 개발 품질 요소


    • 웹 표준

      • 브라우저 종류 및 버전에 따른 기능 차이에 대하여 호환이 가능하도록 제시된 표준

      • 표준화 단체인 W3C(World Wide Consortium)가 권고한 표준안에 따라 웹 사이트를 작성할 때 사용하는 HTML, CSS, JavaScript 등에 대한 규정

    • 웹 접근성

      • 모든 사용자가 신체적, 환경적 조건에 관계 없이 웹에 접근하여 이용할 수 있도록 보장하는 것

      • 한국형 웹 콘텐츠 접근성 지침(Web Content Accessibility Guidelines)

        • 인식의 용이성(perceivable), 운용의 용이성(operable), 이해의 용이성(understandable), 내구성(robust)

    • 웹 호환성

      • 운영체제, 브라우저에 상관없이 유사한 화면으로 동일한 정보에 접근이 가능해야 함

HTML 기본 개념 및 주요 태그

1. HTML 개념

  • 웹 사이트에서 사용할 문서는 웹에 맞는 형식인 html 확장자를 붙여 다른 문서와 구분

  • HTML은 HyperText Markup Language의 줄임말로 웹에서 자유롭게 오갈 수 있는 웹 문서를 만드는 언어

2. HTML 문서 생성

  • Visual Studio Code에서 파일 > 새 파일을 클릭하고, new.html을 입력 후 팝업 되는 창에서 저장 위치 선택

  • new.html이라는 탭이 생성되면 !(느낌표)를 입력하고 Tab 키를 클릭

    • 비주얼 스튜디오 코드에서는 웹 문서의 태그를 자동으로 입력해 주는 이멧(Emmet) 기능 존재

3. HTML 문서 구조

  • 어떤 웹 문서를 작성하든 이 기본 구조를 지켜야 함

    • 웹 브라우저에 표시되는 웹 문서 내용은 <body> 태그와 </body> 태그 사이에 입력

  • Ctrl + S를 눌러 문서를 저장하고, 코드 창에서 마우스 오른쪽 클릭하여 Open With Liver Server 클릭

    • 윈도우 탐색기에서 new.html을 더블클릭해서 실행해도 됨

    • 웹 브라우저에서 127.0.0.1:5500/new.html을 입력하면 코드 수정 시 자동 반영

  • 웹에서 특수 문자 및 특수 기호를 표시할 때는 미리 약속한 이름이나 표기법을 사용

    • 이 표기법을 ‘엔티티(entity) 이름’ 또는 ‘엔티티 기호’라고 함

    • W3C(https://www.w3.org/MarkUp/html3/latin1/html)에서 제공하는 엔티티 코드 표에서 확인

4. HTML의 태그(tag) 사용법

  • 태그는 <와 >를 이용해 구분

    • 웹 브라우저는 <와 > 사이에 있는 문자를 태그로 인식

  • 태그와 태그 안에 사용하는 속성들은 모두 소문자로 사용

    • 맞는 예: <img src = "images/first.jpg">
    • 틀린 예: <IMG src = "images/first.jpg">

  • 여는 태그와 닫는 태그를 정확하게 입력

    • 맞는 예: <h1> 시간이란 </h1>
    • 틀린 예: <h1> 시간이란

  • [Tab] 키를 이용해서 적당히 들여쓰기

    • 들여쓰기의 예
      <ul>
          <li> 메뉴 1 </li>
          <li> 메뉴 2 </li>
      </ul>

  • 태그는 여러 기능을 추가하는 속성과도 함께 사용

    • <태그 속성 = “속성 값” 속성 = “속성 값” …> 형태로 사용
    • 예: <img src = "image/first.jpg" width="350" height="200" alt="시계이미지">

  • 한 태그 안에 다른 태그를 포함시킬 때, 여는 태그와 닫는 태그 쌍을 정확히 맞추어 사용

    • 예: <u> 한국국토정보공사 <i>국토정보교육원</i></u>

11. 폼 만들기

  • 폼(form) 태그

    • 폼(form)은 사용자가 웹 사이트로 정보를 보낼 수 있는 요소

    • <form>과 </form> 태그 사이에 여러 폼 요소와 관련된 태그를 삽입

      • 예: 아이디와 비밀번호 입력창, 로그인 버튼, 회원가입 창 등

  • 폼 태그의 사용

    • <label> 태그: 폼 요소에 레이블을 붙이기 위해 사용

    • <textarea>태그: 여러 줄로 된 텍스트 입력 필드를 나타내는 태그(cols, rows로 길이 설정)

    • <input> 태그: 사용자가 내용을 입력하는 부분을 생성하기 위해 사용

      • id 속성: 여러 번 사용된 폼 요소를 구분하기 위해 사용

      • type 속성: 사용자가 입력할 수 있는 형태를 지정하기 위해 사용
        (예: 라디오 버튼, 체크박스, 텍스트 상자 등)

  • <input> 태그의 type 속성에서 사용 가능한 유형

    • name 속성: 서버에서 폼 요소를 구분하기 위해 이름 지정

    • value 속성: 선택한 라디오버튼이나 체크 박스를 서버로 알려줄 때 넘길 값을 지정

      • button에서 value 속성은 버튼에 표시할 내용 지정

    radio주어진 항목에서 1개만 선택할 수 있는 radio 버튼 삽입

3. 주요 선택자

  • 스타일 속성을 적용하는 요소인 선택자는 태그 하나가 될 수도 있지만 여러 개의 요소를 묶어 별도의 선택자로 지정 가능

    • 전체 선택자

      • 주로 모든 요소에 한꺼번에 스타일을 적용할 때 사용하는 것으로 *(별표)를 사용

    • 태그 선택자

      • 특정 태그가 쓰인 모든 요소에 스타일 적용

    • 그룹 선택자

      • 둘 이상 요소에 같은 스타일을 적용할 때 사용하는 것으로 쉼표(,)로 구분해 여러 선택자를 나열한 후 스타일을 정의

    • 클래스 선택자(여러 번 적용 가능)

      • 특정 부분에만 스타일을 적용할 때 사용하는 것으로 태그 대신 클래스 이름을 사용하고 클래스 이름 앞에 마침표(.)를 붙임(대부분 여러 요소에 같은 스타일)

    • id 선택자(한 번만 적용 가능)

      • 클래스 선택자와 마찬가지로 특정 부분에 스타일을 지정할 때 사용하는데 마침표(.) 대신 # 기호를 사용(페이지에서 딱 하나만 존재하는 요소)

  • color 속성

    • 글자 색을 지정하는 속성으로 색상 값은 16진수나 rgb(또는 rgba), hsl(또는 hsla), 색상 이름으로 표시

      • 16진수: RRGGBB와 같이 표기하고 f가 제일 큰 수치이고, 0이 제일 작은 수치

      • rgb: 0 ~ 255 사이의 숫자로 표기하고 값이 클수록 색상 표현이 큼

      • hsl: 색상(hue) 각도를 기준으로 색상을 둥글게 배치한 색상환으로 표시, 채도(saturation)와 밝기(lightness)는 %로 표시

      • 알파(a): 0 ~ 1 사이의 숫자로 표기하고 0에 가까울수록 투명, 1에 가까울수록 불투명

2. 자바스크립트의 이해

  • 자바스크립트는 프런트엔드 개발 언어이며 정적인 웹 문서에 동작을 부여

    • 웹 페이지에 생동감을 불어넣기 위해 만들어진 프로그래밍 언어

  • 자바스크립트 탄생 배경

    • 브라우저에서 동작하는 언어인 자바스크립트는 1995년 세계 최초의 상용 브라우저인 넷스케이프 내비게이터(Netscape Navigator)를 출시한 넷스케이프 커뮤니케이션즈가 개발

    • 출시 초기에는 라이브스크립트(LiveScript)라는 이름을 가지고 있었지만 당시 유행하던 자바의 영향을 받아 자바스크립트(JavaScript)로 변경

    • 구글 지도의 등장으로 새로운 웹의 가능성과 자바스크립트의 가능성을 인식

      • 당시 구글은 서버에서 반환된 HTML 데이터를 읽어들인 후 지도 확장이나 축소, 슬라이드 등의 동작을 브라우저에서 구현하고자 함

    • 각 브라우저는 자바스크립트를 구동하기 위한 엔진을 갖고 있으며 이를 자바스크립트 가상 머신이라 함

      • Chrom, Opera(V8), FireFox(SpiderMonky), IE(Triden 및 Chakar), Microsoft Edge(ChakraCore), Safari(Nitro 및 SquirrelFish)

    • 국제 정보통신표준화기구(ECMA, European Computer Manufacturers Association)는 1996년부터 자바스크립트 표준화를 시작

      • 각 브라우저 개발사들의 자바스크립트 엔진이 다르고 그에 따른 사용자들의 크로스 브라우징 이슈와 자바스크립트의 파편화를 방지 목적

    • ECMAScript(또는 ES)는 ECMA에 의해 표준화된 범용 프로그래밍 언어로 서로 다른 웹 브라우저들에서 웹 페이지의 상호운용성을 보장하기 위한 자바스크립트 표준

      • ECMAScript는 스크립팅 언어를 어떻게 만들어야 하는지를 설명하는 일종의 설명서이고, 자바스크립트는 ECMAScript의 사양을 바탕으로 만들어진 언어

  • 자바스크립트로 할 수 있는 일

    • Native React라는 프레임워크를 통하여 HTML, CSS, JS 만으로 웹 어플리케이션, 안드로이드 어플리케이션, ISO 어플리케이션을 한 방에 작성 가능

    • three.js 라이브러리를 통해 3D 게임, 애니메이션 등을 제작하고, 데이터 시각화도 가능

      • three.js 사이트(http://threejs.org)에서 확인

    • Electron으로 데스크톱 개발이 가능하고, 윈도우, 맥, 리눅스까지 지원

    • TensorflowJS, BrainJS 등의 라이브러리를 활용하면 적은 파라미터로도 충분한 성능을 보여줄 수 있는 머신러닝 신경망을 학습하고 학습된 모델을 실행시켜 볼 수 있음

1. 상수와 변수

  • 상수(constant)의 개념 및 선언

    • 상수를 만드는 과정은 선언이라고 표현하고, const 키워드를 사용하여 선언

      • “TypeError: Assignment to constatn variable”

    • 변수를 만들 때는 let 키워드를 사용하고, 기본적인 사용 방법은 상수와 같음

      • 카멜 표기법(camelCase)

        • 두 번째 이후 단어의 대문자 부분이 낙타의 혹처럼 보인다고 해서 지어진 이름으로 두 번째 이후 단어의 첫 글자를 대문자로 표기
        • 사용 예: newName, createLifeGame

      • 파스칼 표기법(PascalCase)

        • 프로그래밍 언어 파스칼에서 사용된 표기법으로 각 단어의 첫 글자를 모두 대문자로 표기
        • 사용 예: NewName, CreateLifeGame

        • 모든 단어를 소문자로 표기하며, 단어 사이사이에 언더바(_)를 넣어 표기
        • 사용 예: new_name, create_life_game

2. 연산자(Operator)

  • 연산자란?

    • 빼기, 더하기, 곱하기, 나누기, 비교 등을 하는 일련의 작업을 연산작업이라 함

    • 연산자는 연산을 수행하는 기호를 의미하고, 피연산자는 연산에 참여하는 변수나 상수의 값을 의미

  • 산술연산자

    • 연산을 하기 위해서는 연산 대상 데이터가 반드시 2개 있어야 함

    종류기본형설명
    +A + B더하기
    -A - B빼기
    *A * B곱하기
    /A / B나누기
    %A % B나머지

  • 문자 결합 연산자

    • 여러 개의 문자를 하나의 문자형 데이터로 결합할 때 사용

    • 더하기에 피연산자로 문자형 데이터가 한 개라도 포함되어 있으면 다른 피연산자의 데이터는 자동으로 문자형으로 형 변환

      • 문자형 데이터 + 문자형 데이터 = 하나의 문자형 데이터
      • 문자형 데이터 + 숫자형 데이터 = 하나의 문자형 데이터

      예제 코드 보기/숨기기(클릭) 
      //Chrome 창에서 개발자도구(F12) > Console 탭 활용 실습
let t1 = "학교종이";
let t2 = "땡땡땡";
let t3 = 8282;
let t4 = "어서 모이자";
let result

result = t1 + t2 + t3 + t4;

typeof(result)

  • 대입 연산자

    • 대입 연산자(=)는 연산된 데이터를 변수에 저장할 때 사용

    • 복합 대입 연산자(-=, +=, *=, /=, %=)는 산술 연산자와 대입 연산자가 복합적으로 적용된 것

    종류설명
    A = BA = B
    A += BA = A + B
    A -= BA = A - B
    A *= BA = A * B
    A /= BA = A / B
    A %= BA = A % B

    예제 코드 보기/숨기기(클릭) 
      ```JavaScript
  //Visual Studio Code에서 실습
  let num1 = 10;
  let num2 = 3;

  num1 += num2;      //num1 = 10 + 3 = 13
  document.write(num1, "<br>");

  num1 -= num2;      //num1 = 13 - 3 = 10
  document.write(num1, "<br>");

  num1 *= num2;      //num1 = 10 * 3 = 30
  document.write(num1, "<br>");

  num1 /= num2;      //num1 = 30 / 3 = 10
  document.write(num1, "<br>");

  num1 %= num2;      //num1 = 10 % 3 = 1
  document.write(num1, "<br>");
  ```

  • 증감 연산자

    • 숫자형 데이터를 1씩 증가시키는 증가 연산자(++)와 반대로 1씩 감소시키는 감소 연산자(--)가 있음

    • 피 연산자가 한 개만 필요한 단항 연산자

    • 증감 연산자는 변수의 어느 위치에 오는가에 따라 결과값이 달라짐

      • 기본형: ++변수, 변수++, --변수, 변수--



    예제 코드 보기/숨기기(클릭) 
    //Visual Studio Code에서 실습
let num1 = 10;
let num2 = 20;
let result;

result = ++num1;             //num1이 원래 10인데 ++가 앞에 있으므로 1을 증가시키고 result에 대입
document.write(result, "<br>");

result = num1++;             //위의 결과에서 num1이 11로 바뀌고 ++가 뒤에 있으므로 바로 result에 대입
document.write(result, "<br>");

result = --num2;             //num1이 원래 20인데 --가 앞에 있으므로 1을 감소시키고 result에 대입
document.write(result, "<br>");

//result 추가 복사해서 왜 그런지 살펴보기!!
result = num2--;             //위의 결과에서 num2가 19로 바뀌고 --가 뒤에 있으므로 바로 result에 대입
document.write(result, "<br>");

  • 비교 연산자

    • 두 데이터를 비교할 때 사용하는 연산자로 결과값은 true(참), false(거짓)로 논리형 데이터를 반환

    종류설명비고
    A > BA가 B보다 크다.
    A < BA가 B보다 작다.
    A >= BA가 B보다 크거나 같다.
    A <= BA가 B보다 작거나 같다.
    A == BA와 B는 같다.숫자의 자료형에 상관없이 결과 반환
    A != BA와 B는 다르다.숫자의 자료형에 상관없이 결과 반환
    A ===BA와 B는 같다.반드시 표기된 숫자와 자료형이 일치해야만 결과 반환
    A !==BA와 B는 다르다.반드시 표기된 숫자와 자료형이 일치해야만 결과 반환

document.write(result, "<br">);

  • 논리 연산자

    • 피 연산자가 논리형 데이터인 true, false로 결과값을 반환

    종류설명
    ||or 연산자로 피 연산자 중 값이 하나라도 true가 존재하면 true로 결과값을 반환
    &&and 연산자로 피 연산자 중 값이 하나라도 false가 존재하면 false로 결과값을 반환
    !not 연산자로 피 연산자의 값이 true면 반대로 false로 결과값을 반환

제어문

1. 제어문이란?

  • 프로그램의 흐름을 제어할 수 있도록 도와주는 문장

    • 조건문(if문 / else문 / else if문)

      • 조건에 따라 특정 코드를 실행

    • 선택문(switch문)

      • 일치하는 경우의 값이 있을 경우에만 특정 코드를 실행

    • 반복문(while문 / for문)

      • 코드를 지정한 횟수만큼 반복해서 실행

2. 조건문

  • if문

    • 조건식의 값이 참(true)인지 거짓(false)인지에 따라 자바스크립트 코드를 제어

    • if문은 조건식을 만족할 경우에만 코드를 실행

      • 10,000보 이상일 경우 “매우 좋은 습관을 지니고 계시는군요!!” 출력

  • else문

    • 조건식을 만족할 경우(true)와 만족하지 않을 경우(false)에 따라 실행되는 코드가 달라짐

    • 방문자에게 질의응답 창으로 좋아하는 숫자를 입력 받고 입력된 값이 짝수인지, 홀수인지에 따라 출력되는 결과가 다르게 나타나도록 작성해 봅시다.

      정답 코드 보기/숨기기(클릭)

함수

1. 함수의 기본 형태

  • 함수의 개념

    • 함수는 코드의 집합을 나타내는 자료형으로 함수를 사용하는 것을 함수 호출이라 표현

      • 리턴값: 함수를 호출해서 최종적으로 나오는 결과

      • 반복되는 코드를 한 번만 정의해 놓고 필요할 때마다 호출하므로 반복 작업을 피할 수 있음

      • 기능별(함수별)로 수정이 가능하므로 유지보수가 쉬움

  • 객체의 종류

    • 내장객체

      • 자바스크립트 엔진에 내장되어 있어 필요한 경우에 생성해서 사용 가능
        (예: 문자(String), 날짜(Date), 배열(Array), 수학(Math) 객체 등)

        (예: window, screen, location, history, navigation 객체 등)

      • HTML 문서 구조를 객체로 표현한 것
        (예: open, prompt, confirm, alert 객체 등)

2. 문서 객체 모델

  • DOM tree의 구조

    • 브라우저가 이해할 수 있는 형태로 HTML 문서를 모델로 구성하여 메모리에 생성되는데, 이때 모델은 객체의 트리로 구성

      • 하나의 최상위 노드(node)에서 다른 자식 노드들이 뻗어나가는 구조로 트리(나무가지) 자료 구조라 함

      • 문서노드(document node):DOM tree에 접근하기 위한 시작점으로 최상위에 존재

      • 요소 노드(element node): <html>, <body>, <div> 등 html의 요소를 표현

      • 어트리뷰트 노드(attribute node): HTML 요소의 attribute로 HTML 요소의 자식이 아닌 일부

      • 텍스트 노드(text node): DOM tree의 최하단에 있는 노드로 텍스트로 표현된 요소 노드의 자식 요소

    • HTML의 모든 요소와 요소의 attribute, text 등을 각각의 객체로 만들고, 이들 관계를 부자 관계로 표현

      • <body>는 <html>의 자식 노드(child node), <head>와 형제 노드(sibling node), <a> 태그의 부모 노드(parent node)

  • DOM 요소 접근

    • getElementById( ) 메서드

      • HTML 문서 내에서 주어진 문자열과 값이 일치하는 id 속성의 값을 가진 요소 객체를 반환

      • id 속성의 값은 HTML에서 고유하고 유일해야 하기 때문에 이 함수를 사용해서 요소를 빠르게 찾을 때 유용

    • getElementById( ).value 메서드

      • getElementById로 반환된 객체에 입력된 실제 값을 반환

      • getElementById( )는 요소의 속성이나 스타일을 변경할 때, getElementById( ).value는 input/textarea 등의 입력 데이터를 가져오거나 넣을 때 사용

    • <input>으로 다음 그림과 같이 나타나도록 HTML 태그를 작성하고, 이름 란에 방문자가 이름을 입력하고 인사하기 버튼을 클릭하면 입력한 값을 가져와서 메세지를 출력해 봅시다.

      • 출력 메세지: 이름님 환영합니다.

      • isNaN( ) 함수: 어떤 값이 NaN(Not a Number)인지를 판별하는 함수로 앞에 느낌표(!)를 붙이면 논리값이 반대로 뒤집힘

    • GIS 프로그램
    • AI 프로그램

node.js 기반 개발

node.js는 자바스크립트 개발에 혁명을 일으켰다.

  • 예전

    • 웹서버는 별도 프로그램 이용(tomcat 등)
    • 프로그램 수정할 때마다 tomcat으로 전송해서 내용 확인

  • 현재: node.js는 윈도우용 프로그램 개발 가능

    • 윈도우용 웹서버 개발 가능
    • 웹개발에 이 웹서버를 이용
    • 실시간으로 결과를 보며 쉽게 자바스크립트 개발

  • node.js 자체를 이용하는 개발도 활발하지만,

  • 대부분 자바스크립트 개발자들은 node.js의 도움을 받아 react, vite 등으로 개발

react

  • 현 메타(구 페이스북)에서 개발한 웹 개발 프레임워크
  • javascript 개발을 위한 최신 기술

vite

  • react 등 웹을 이용한 개발 최종 결과물을 만들어 내는(build) 도구
  • build 할 때는 node.js를 이용하지만 build한 결과물은 node.js가 없어도 됨.

react의 상태 관리 매커니즘

상태

  • 게임에서의 상태: 플레이어의 에너지 양, 적군의 에너지 양, 남은 총알 수 등
  • 이 샘플 프로젝트에서는 버튼을 누른 시간이 상태 관리의 대상임.

상태는 변수와 다른가?

let  a = 1
let  b= 2
let  c= a +b

위와 같은 a, b, c는 상태가 아닌 그냥 변수임

변수와 상태의 다른 점

  • 변수는 그냥 값 저장
  • 상태는 UI와의 연계를 기반으로 한다.

상태로 관리되는 값이 변경되면 화면에 표시된 값도 바뀐다.

  • d를 상태로 관리하면, d의 값이 바뀌는 순간 화면에 표시된 d의 값도 자동으로 바뀐다.
